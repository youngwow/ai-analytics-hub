# GS Labs Radar — pilot MVP

Рабочая вертикаль поверх общего продуктового ядра репозитория. В папке нет
отдельной benchmark-логики: backend использует те же адаптеры, контракты,
хранилище и AI-компоненты, которые проверялись B1–B4.

## Запуск

```bash
.venv/bin/python -m MVP.backend.app --port 3002 --live --interval 600 --news-active-days 30
```

Открыть: <http://127.0.0.1:3002>

### Docker

```bash
docker compose up --build -d
docker compose ps
```

Открыть: <http://127.0.0.1:3002>. Настройки берутся из корневого `.env`, а
рабочая БД и Telegram-сессия сохраняются на хосте в `MVP/data/` и `data/`.
Остановить приложение: `docker compose down`.

`--live --interval 600` включает фоновый цикл раз в 10 минут. Без флага сбор и
AI запускаются кнопкой «Собрать сейчас» — это безопаснее для репетиции и не
расходует API-кредиты в фоне. Кнопки «Обновить источники» и «Запустить анализ»
позволяют показать стадии раздельно.

## Данные и границы

- рабочая БД: `MVP/data/pilot.db` (локальная, не коммитится);
- рабочий контекст: `MVP/context.json`; исходный Context Truth B4 остаётся неизменным доказательным артефактом;
- источники: корневой `sources.json`;
- генерация: `glm-5.3-flash:cloud` через Ollama;
- embeddings: `google/gemini-embedding-001` через OpenRouter;
- целевой доресерч: Tavily;
- архитектурная ветка: `one_pass + targeted_research + embedding_top20 + without_critic`.

Интерфейс показывает весь проверяемый путь: реальные входные материалы,
общую очередь с фильтрами `Все / PR / GR`, карточку с evidence и оригиналом,
НПА, активный и архивный банк событий, сборку одного общего выпуска, источники,
версионируемый контекст и audit trail.

Обычные события остаются активными 30 дней после последнего содержательного
изменения, затем логически архивируются. Архив остаётся в embeddings-поиске и
может реактивироваться новым фактом. НПА живут по отдельному долгому циклу.
Физическое удаление данных в пилоте отключено; порог активности можно изменить аргументом
`--news-active-days`, не меняя модель данных.

Первичный сбор сохраняет реальные оригиналы и их происхождение. Синтетические
данные B3 в пилотную БД не импортируются. Ошибки источников и AI показываются в
интерфейсе, а не маскируются.

Рабочая SQLite-база является runtime-данными и не коммитится. Повторяемое
наполнение начинается с `sources.json` и подтверждённого Context Truth; историю
можно заново получить штатным сбором без импорта синтетики из бенчмарков.
