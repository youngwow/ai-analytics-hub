# A1 — решение по development

> **Решение:** двухэтапный вариант убит; для следующего сравнения выбран `one_pass`.

Одинаковыми были dataset `v1.0.0`, split `development`, модель `glm-5.3-flash:cloud`, полный банк событий и отсутствие критика. Менялся только A1.

| Метрика | One-pass | Two-pass |
|---|---:|---:|
| Релевантность | 82.4% | 76.5% |
| Важность | 64.7% | 58.8% |
| Роли, exact set | 29.4% | 23.5% |
| Critical/escalate | 100% | 100% |
| Verbatim evidence | 100% | 100% |
| Event pair F1 | 61.5%* | 50.0%* |
| Вызовы модели | 26 | 41 |
| Wall time | 360 с | 797 с |

Two-pass не дал защитного выигрыша, ухудшил все измеряемые смысловые показатели и потребовал в 1.58 раза больше вызовов и в 2.21 раза больше времени. Поэтому усложнение не переносится в MVP.

\* Event F1 оставлен как диагностика, но не участвует в решении A1: после прогона найден нарушенный output-контракт EventLinker. Он одинаков в обоих вариантах; A1 убит по собственным метрикам и цене.

Это решение относится к данной реализации промптов и модели, а не доказывает универсальное превосходство one-pass.

Артефакты:

- `runs/dev_a1_onepass_a3_full_a4_off_v1/`
- `runs/dev_a1_twopass_a3_full_a4_off_v1/`

## Найденный дефект следующей проверки

Текущий `B2-E` проверяет корректность событий, но каждый локальный банк содержит меньше 20 событий. Поэтому он не различает полный обход и embedding top-20 и не может честно закрыть A3. До запуска A3 нужен отдельный retrieval-контракт внутри B2 с банком больше 20 и скрытой истинной связью; существующие результаты A1 при этом не пересчитываются.
