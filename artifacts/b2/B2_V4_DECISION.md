# B2 v4 — решение после свежего holdout

## Решение

Выбранная конфигурация технически стабильна, но **не принята для автономной публикации**. Она остаётся кандидатом для review-first MVP: AI готовит рабочий черновик, PR/GR видит источники и подтверждает результат.

Конфигурация: `one_pass + glm-5.3-flash:cloud + full_scan + without_critic`, temperature `0.2`, четыре параллельных независимых анализа.

## Почему

На одном замороженном holdout выполнены три неизменных повтора:

| Проверка | Результат трёх повторов | Вывод |
|---|---:|---|
| Проваленные model calls | `0 / 0 / 0` | runtime стабилен на этом объёме |
| Релевантность | `9/19`, `8/19`, `9/19` | недостаточно для автономного отбора |
| Важность | `13/18`, `12/18`, `13/18` | полезный, но не достаточный сигнал |
| Роли целиком | `10/19`, `11/19`, `11/19` | адресную выдачу нельзя выпускать без проверки |
| Связанные пары событий | `1/3`, `2/3`, `2/3` | ложных объединений нет, но есть недообъединение |
| Evidence quotes | все дословно присутствуют в исходниках | технический grounding выдержан; полнота смысла здесь не доказана |

Нельзя превращать это в один средний score: сильная важность не компенсирует слабую релевантность или неверную роль.

## Насколько надёжен сам holdout

- `27` свежих материалов появились только после заморозки prompt/config.
- Два слепых независимых LLM-аудита совпали по смысловым полям только на `18–19` материалах; несовпавшие поля исключены из расчёта.
- Критичность совпала на всех `27`, но в holdout нет положительного критичного примера, поэтому это не доказательство recall критичного.
- Метки являются внутренним proxy по Context Truth, а не customer gold GS Labs.
- Свободный текст не свёрнут в искусственный процент. Его содержательную достаточность отдельно проверяет B4 по must-have/must-not-have и источникам.

## Зафиксированные решения по развилкам

- `A1`: one-pass оставлен — два прохода не дали соразмерного прироста и существенно увеличили latency.
- `A5`: GLM оставлена как лучший сбалансированный кандидат validation-матрицы; holdout не использовался для повторного выбора модели.
- `A3`: full scan оставлен на текущем размере банка; embedding top-20 не был быстрее на малом изолированном наборе. Решение ограничено масштабом.
- `A4`: critic убит в текущем виде: увеличил вызовы и ухудшил обнаружение ошибок.
- `A2`: доресерч не решён B2; сравнение без/с research проводится внутри B3 на одинаковом E2E-потоке.
- НПА: свежий holdout не содержит полноценной новой траектории; обязательный NPA-контракт остаётся отдельным validation/B3 evidence, а не выводом из этих 27 материалов.

## Допустимая формулировка

> На свежем внутреннем holdout контур стабильно сформировал grounded-черновики, но качество отбора, ролей и событий недостаточно для автономного выпуска. Поэтому архитектура фиксируется как review-first, а содержательная полезность проверяется дальше в B3/B4.
