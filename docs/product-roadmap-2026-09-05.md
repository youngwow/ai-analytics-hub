# Roadmap (2026-09-06)

## 1. Пользовательские сценарии и болевые точки

**Сценарий A. «Утренний обзор» (GR/PR-специалист).**
Открывает ленту → фильтрует high за сегодня → видит пометки «Обработка неполная» → правит, скрывает, добавляет заметки.
Боли: (1) автосбор включается вручную после каждого рестарта; (2) «показать только деградированные за ночь» — фильтра нет, карточки ищутся глазами; (3) если LLM был недоступен ночью, чинить деградированные карточки можно только массовым перепрогоном (`force=true`) — точечной кнопки reprocess нет.

**Сценарий B. «Дайджест руководителю» (еженедельно).**
Открывает DigestView → «За 7 дней» → сформировать → правит текст → экспорт файла → **вручную вставляет в письмо/чат**.
Боли: доставка полностью ручная; повторяемость — заново те же клики; нет истории сгенерированных дайджестов («а что отправляли на прошлой неделе?»).

**Сценарий C. «Ведение реестра НПА» (GR).**
Открывает раздел НПА → по каждому акту: добавить событие/срок из карточки, статус НПА двигается автоматически при статусе из словаря.
Статус: **боль снята** — события добавляются из UI; осталась одна CLI-операция вокруг карточки — `reprocess` (см. A).

**Сценарий D. «Эксплуатация системы» (small team).**
Панель «Сбор и обработка» → запустить прогон/мониторинг → следит за историей прогонов; источники: «Опросить»/«Пауза»/история опросов — всё из UI.
Боли: (1) рестарт API тихо убивает автосбор; (2) качество LLM (доля деградаций, латентность, доля правок) — только `make quality` в терминале; (3) сбойные документы прогона (failed) не персонализированы — повторить только сбойные нельзя.

## 2. Бэклог фич по категориям

### Автоматизация

| Фича | Сценарий | Ценность | Оценка |
|---|---|---|---|
| **A2. Автопрогон обработки после сбора** | После collection-цикла с новыми документами автоматически запускать processing-прогон (или чекать очередь в watcher-тике) | Высокая |
| **N1. Панель качества обработки в UI** | Раздел «Качество модели»: то, что сегодня `make quality` — деградации, доля правок, p95 латентности, failed calls, `edited_share` | Низкая |
| **N3. Фильтр `degraded` в ленте** | «Показать деградированные за ночь → починить» — degraded реально наполняется, фильтра нет | Низкая | **S** | feed.py SQL (1 условие), queries.py, FilterBar/NewsFeed | нет |
| **Q1. Кнопка reprocess в карточке** | На деградированной/плохой карточке — «Пересобрать моделью» без потери правок (`keep_human_edits=True`); service-метод готов (processing_service.py:639), нет маршрута и кнопки | Низкая |
| **Q2. Массовый reprocess деградированных** | «Показать деградированные → пересобрать все» — по сути processing run с `since`+`force`, но точечно по флагу degraded | Низкая |
| **C2. Сохранение дайджестов (история)** | Таблица `digests` (title, body, filters, generated_at) + список в UI + переотправка | Низкая |
| **I2. RSS-экспорт ленты** | Отдать срез ленты как RSS → внешние читалки | Низкая |

## 3. Дальний горизонт (не подтверждены текущей болью, не в приоритетах)

- Автоматическое управление жизнью НПА (автодетект статусов из новостей) — ручной ввод событий закрывает сценарий.
- ML-переранжирование ленты и рекомендация источников (приоритизация решается failsafe-пайплайном — признаков потребности нет).
