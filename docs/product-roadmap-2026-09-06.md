# Roadmap (2026-09-06)

## 1. Пользовательские сценарии и болевые точки

**Сценарий A. «Утренний обзор» (GR/PR-специалист).**
Открывает ленту → фильтрует high за сегодня → видит пометки «Обработка неполная» → правит, скрывает, добавляет заметки.
Боли: (1) автосбор включается вручную после каждого рестарта; (2) «показать только деградированные за ночь» — фильтра нет, карточки ищутся глазами; (3) если LLM был недоступен ночью, чинить деградированные карточки можно только массовым перепрогоном (`force=true`) — точечной кнопки reprocess нет (HTTP-маршрута `/items/{id}/reprocess` нет, service-метод `reprocess()` готов и вызывается только из CLI); (4) карточки-дубли одного события: SimHash не ловит авторские пересказы, а косинус по эмбеддингам фактически выключен (Ollama Cloud отвечает 401 на `embed`, `_embed` молча деградирует) — в ленте по одному событию несколько карточек, аналитик находит и прячет их руками через bulk-скрытие каждый день.

**Сценарий B. «Дайджест руководителю» (еженедельно).**
Открывает DigestView → «За 7 дней» → сформировать → правит текст → экспорт файла → **вручную вставляет в письмо/чат**.
Боли: (1) доставка полностью ручная; (2) повторяемость — заново те же клики; (3) нет истории сгенерированных дайджестов («а что отправляли на прошлой неделе?»); (4) из-за пропущенных парафразов (дедуп по эмбеддингам мёртв, см. A-4) одно событие может попасть в дайджест дважды — двумя карточками, что подрывает доверие руководителя к выгрузке.

**Сценарий C. «Ведение реестра НПА» (GR).**
Открывает раздел НПА → по каждому акту: добавить событие/срок из карточки, статус НПА двигается автоматически при статусе из словаря.
Статус: **боль снята** — события добавляются из UI; осталась одна CLI-операция вокруг карточки — `reprocess` (см. A).

**Сценарий D. «Эксплуатация системы» (small team).**
Панель «Сбор и обработка» → запустить прогон/мониторинг → следит за историей прогонов и результатами каждого; источники: «Опросить»/«Пауза»/история опросов — всё из UI.
Боли: (1) рестарт API тихо убивает автосбор — состояние наблюдателя не хранится, после рестарта `running: false` и его включает руками; (2) панель качества не подключена к UI: маршрут `GET /processing/quality` уже отдаёт деградации, долю правок, латентность и failed calls (тот же `quality_summary`, что у `make quality`), но фронтенд его не вызывает; (3) повтор только сбойных документов недоступен из UI: сбой помечается на самом документе (`mark_failed`) и API принимает `only_failed=true`, но в форме прогона (WorkerControls) галочки нет — повторять сбойные приходится через CLI или Swagger.

**Сценарий E. «Ручная уборка дублей» (GR/PR-специалист, ежедневно).**
Одно событие выходит в нескольких СМИ — ТАСС пишет коротко, Коммерсантъ развёрнуто, Telegram-каналы пересказывают своими словами → в ленте появляется 2–4 карточки одного события; перед дайджестом аналитик **вручную** просматривает ленту, находит глазами повторы (SimHash не ловит авторские пересказы, косинус по эмбеддингам мёртв — 401 на `embed`) и прячет дубли через bulk-скрытие.
Боли: (1) дедуп на входе (S1) фактически выключен — парафразы проходят сквозь сбор как «разные документы», каждый плодит свой вызов LLM и свою карточку; (2) чистка дублей — регулярная ручная работа без инструментов: ни подсказки «вероятный дубль», ни кнопки объединения карточек; (3) пропущенный вручную дубль доходит до руководителя в дайджесте (см. B-4).

## 2. Бэклог фич

| Фича | Сценарий | Ценность |
|---|---|---|
| **Автопрогон обработки после сбора** | После collection-цикла с новыми документами автоматически запускать processing-прогон (или чекать очередь в watcher-тике) | Высокая |
| **Подключить панель качества к UI** | Раздел «Качество модели» поверх готового маршрута `GET /processing/quality` (деградации, доля правок, латентность, failed calls, `edited_share`): маршрут есть, фронтенд его не вызывает — нужна только вёрстка в WorkerControls | Низкая |
| **Галочка «только сбойные» в форме прогона** | Добавить в WorkerControls чекбокс `only_failed` — API и БД готовы (`mark_failed`, параметр `only_failed` у `POST /processing/runs`), не хватает одного поля формы | Низкая |
| **Фильтр `degraded` в ленте** | «Показать деградированные за ночь → починить» — флаг в ленте отображается, фильтра в `FeedQuery` и SQL нет | Низкая |
| **Кнопка reprocess в карточке** | На деградированной/плохой карточке — «Пересобрать моделью» без потери правок (`keep_human_edits=True`); service-метод готов (processing_service.py:710), нет маршрута и кнопки | Низкая |
| **Массовый reprocess деградированных** | «Показать деградированные → пересобрать все» — по сути processing run с `since`+`force`, но точечно по флагу degraded | Низкая |
| **Сохранение дайджестов (история)** | Таблица `digests` (title, body, filters, generated_at) + список в UI + переотправка | Низкая |
| **RSS-экспорт ленты** | Отдать срез ленты как RSS → внешние читалки | Низкая |
| **Дедупликация через эмбеддинги** | Снимает боли E(1): сейчас косинусная кластеризация перепечаток (S1) фактически выключена — Ollama Cloud отвечает 401 на `embed`, `_embed` молча деградирует до SimHash, и парафразы (переписанные другими словами перепечатки) плодят лишние карточки и лишние вызовы LLM. Решение без новой инфраструктуры и 401: локальные эмбеддинги `ai-sage/Giga-Embeddings-instruct` (выбрать из `config.yaml`) после нормализации; зависимости `sentence_transformers` + `torch` (device="mps"/"cuda") | Средняя |
| **Вторая дедупликация: кластеризация карточек по эмбеддингам саммари** | Снимает боли E(2), E(3) и B(4). Как работает: (1) после прогона обработки считаем эмбеддинги саммари свежих карточек; (2) нормализуем эмбеддинги; (3) уменьшаем размерность через UMAP (можно попробовать еще PCA, t-SNE); (4) кластеризуем их HDBSCAN на пространстве косинусной близости — он сам находит группы дублей, без фиксированного порога `cosine_threshold` и без предположения «сколько всего событий»; одиночные карточки уходят в шум (label=-1) и не трогаются; (5) кластеры ≠ автосклейка: показываем на карточке «вероятный дубль — объединить?» по образцу model_proposals, объединение подтверждает аналитик. Отличие от S1: S1 до модели экономит вызовы LLM на перепечатках, эта фича после модели убирает уже созданные дубли из ленты и дайджеста. Ограничения: `min_cluster_size` (по-умолчанию, 5), `min_samples` (по-умолчанию, 5) и метрику (косинус через нормированные векторы) калибровать на золотом наборе, расширив его парами «дубль/не дубль»; нужна логика union кластеров + перелинковка `item_sources` (без миграций); НПА не касается; одна новая зависимость `hdbscan` (CPU, без инфраструктуры) | Средняя |

## 3. Дальний горизонт (не подтверждены текущей болью, не в приоритетах)

- Автоматическое управление жизнью НПА (автодетект статусов из новостей) — ручной ввод событий закрывает сценарий.
- ML-переранжирование ленты и рекомендация источников (приоритизация решается failsafe-пайплайном — признаков потребности нет).
