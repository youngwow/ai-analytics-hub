# Аудит реализации перед вертикальным MVP

Дата фиксации: 2026-09-06.

## Переиспользуем

- адаптеры RSS, Telegram, HTML, sitemap и Tavily;
- resolver, bounded HTTP-клиент, нормализацию и текущую SQLite-основу;
- B1 и подготовленные наборы B2/B3;
- интерфейсы генеративной модели и embeddings.

## Переписываем в новом контуре

- первичный AI-анализ: единый контракт `AnalysisDraft` и сравнение A1;
- доресерч A2: только GLM с Tavily, с сохранением запросов и доказательств;
- событийную дедубликацию A3: embeddings дают только top-20, окончательное решение принимает GLM;
- критика A4: отдельный версионируемый результат, а не скрытая правка;
- подготовку материала: отдельный `PreparedDocument`, не перезаписывающий сырой вход.

## Добавляем

- три блока контекста `common / pr / gr`;
- версии анализа, evidence, исследования и решений человека;
- события и отдельный жизненный цикл НПА;
- прозрачную очередь PR/GR, общий черновик дайджеста, доставку и audit trail;
- раннеры B2/RAT поверх единого headless-интерфейса.

## Замороженные границы

- генерация: только Ollama Cloud, `glm-5.3-flash:cloud`;
- embeddings: только OpenRouter, `google/gemini-embedding-001`, 3072 измерения;
- поиск: только Tavily;
- никакого скрытого provider/model fallback;
- модель не публикует результат и не объединяет события по одному cosine score.

## Вывод

Старый collector стал фундаментом новой исполняемой вертикали `src/product`, а batch CLI связывает сохранённые документы с подготовкой, анализом, research, событиями/НПА и рабочей очередью. Значимые состояния сохраняются версиями, provider fallback запрещён. Локальный gate пройден: `1092` теста и Ruff без ошибок.

`B2 v2` при этом не пройден: три holdout-повтора выявили системный timeout объединённого NPA-вызова. Это не отменяет готовность backend-контракта, но блокирует утверждение AI-конфигурации. В следующей версии связь пары и стадия НПА разделены на малые ограниченные вызовы; результат должен быть подтверждён новым прогоном, а не заявлен по коду.
