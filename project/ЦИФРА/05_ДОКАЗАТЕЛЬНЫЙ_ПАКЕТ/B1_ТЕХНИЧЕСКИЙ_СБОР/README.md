# B1 — технический сбор

> **Вердикт: PASS.** Текущий ingestion-контур технически пригоден для MVP на проверенных поверхностях. Единственное видимое live-ограничение — стабильный `partial` одного дочернего sitemap РФРИТ.

## Один вопрос

Может ли система надёжно получить доступные материалы из настроенных источников, сохранить их как `RawDocument`, не плодить дубли, не скрывать сбои и давать одинаковый результат при выбранной параллельности?

## Почему нужен отдельный B1

Если сбор нестабилен, B2–B4 будут оценивать не AI, а случайно неполный вход. Поэтому B1 намеренно не решает, полезна ли новость GS Labs: он изолирует транспорт, нормализацию, состояние и воспроизводимость.

## Что находится внутри

```text
замороженные fixtures ─┐
fault-сценарии ─────────┼→ Adapter.fetch → Collector → SQLite → технический отчёт
live active sources ────┤
saved replay bytes ─────┘
```

### Вход

- RSS/Atom, Telegram web-preview, HTML list/diff, sitemap, Tavily transport и fulltext;
- замороженный exact-manifest;
- сценарии `304`, cursor, retry, `403/429/500`, timeout и повреждённый формат;
- одинаковый saved snapshot для `concurrency=1/8/24`;
- 44 активных источника и 9 выключенных диагностических входов.

### Работа

1. Проверяет точный контракт каждого адаптера.
2. Проверяет checkpoint, повтор, восстановление и изоляцию отказов.
3. Гонит один и тот же snapshot через полный Collector при разной параллельности.
4. Выполняет три умеренных live-прохода без нагрузочной атаки на чужие сайты.
5. Проверяет обязательные поля и отсутствие секретов в артефактах.

### Выход

- документы и их fingerprints;
- `ok / partial / failed` по каждому источнику;
- latency, wall time, CPU/RSS и fulltext outcome;
- capture/index без credentials;
- выбранная конфигурация ingestion.

## Результат тезисно

| Проверка | Получено | Решение |
|---|---:|---|
| Exact contract | 8/8 сценариев; exact recall 100%, false positives 0 | Адаптеры соответствуют замороженному контракту |
| State/fault | Все критичные сценарии прошли; повтор создаёт 0 новых записей | Checkpoint и recovery допущены |
| Collector replay | 33 документа, один fingerprint при `1/8/24`, replay misses 0 | Результат не зависит от порядка потоков |
| Concurrency | 1609 / 816 / 780 мс для `1/8/24` | Выбрано `8`: с 24 практическая ничья, но проще |
| Live active | 132 попытки: 129 `ok`, 3 `partial`, 0 `failed` | Текущие входы пригодны для MVP |
| Fulltext live | 90/90 попыток извлечены | Полный текст технически доступен на проверенном окне |
| Секреты | 0 попаданий в сохранённые артефакты | Capture безопасен для репозитория |

## Что закрыл B1

- доказал техническую основу `P1` — разрозненный ручной сбор можно заменить воспроизводимым ingestion;
- дал честный transport baseline для `H1`, но не оценивал смысловую ценность Tavily;
- заморозил `concurrency=8` и правила деградации;
- дал реальные форматы входа для проектирования корзины B2.

## Чего B1 не утверждает

- абсолютную полноту интернета;
- релевантность GS Labs и отсутствие смыслового шума;
- Telegram MTProto как обязательный транспорт;
- SLA `публикация → лента`: без длительно работающего scheduler это только расчётный ориентир.
