# B2 — отдельные AI-механизмы

> **Вердикт:** выбран технически стабильный `one-pass + glm-5.3-flash:cloud + without_critic`, но только для review-first MVP. B2 сознательно не выдал слабый AI за автономного редактора.

## Один вопрос

Какая AI-конфигурация лучше решает отдельные задачи агента на одинаковых замороженных материалах, если менять только одну развилку за раз?

## Почему нужен отдельный B2

B3 не должен одновременно выяснять, какая модель, сколько AI-проходов и нужен ли critic. B2 изолирует компоненты, выбирает конфигурацию и только затем передаёт её в полный E2E.

## Что находится внутри

```text
development ── настройка общих prompt-правил
validation  ── выбор A1 × модель и component EXP
freeze      ── модель + prompt + schema + параметры
fresh holdout ── три неизменных повтора без донастройки
```

### Вход

- корзина v4: 119 материалов, 15 событийных кейсов и 6 траекторий НПА;
- real-flow, case-anchor, challenge и rare-safety слои;
- Context Truth, must-have/must-not-have, роли, importance, event/NPA gold;
- свежий post-freeze holdout: 27 материалов, из них согласованный смысловой gold доступен для 18–19 полей/объектов.

### Работа

1. На development дорабатывает общие prompt-правила, не ответы отдельных кейсов.
2. На validation сравнивает один и два AI-прохода и три модели.
3. Отдельно проверяет critic и обязательные NPA-контракты.
4. Замораживает выбранную конфигурацию.
5. Выполняет три одинаковых holdout-run и показывает каждый результат отдельно.

### Выход

- выбранные модель, prompt-контур и review-policy;
- predictions, execution, deterministic reports и замороженные config/hash;
- убитые варианты и известные ошибки;
- конфигурация для B3.

## Главные результаты

| Развилка | Факт | Решение |
|---|---|---|
| `A1`: one-pass / two-pass | Two-pass не дал соразмерного прироста, validation wall time вырос 244→642 с | **Two-pass убит**, выбран one-pass |
| `A5`: три модели | Худшая core-метрика: GLM 41,4%; DeepSeek 31,0%; GPT-OSS 27,6% | **Выбрана GLM** для продуктового runtime |
| `A4`: without / critic | Critic не улучшил классификации, добавил 18 вызовов и 210 с; ранний EXP дал +583 с | **Critic убит** |
| NPA quality | После разделения контрактов: identity 91,7%, relation 91,7%, stage 100% | Контракт сохранён, спорное остаётся review-first |
| Fresh holdout | 0 failed model calls во всех трёх повторах; evidence дословно grounded | Runtime стабилен на этом объёме |
| Fresh holdout quality | relevance 8–9/19; importance 12–13/18; roles 10–11/19; event pairs 1–2/3 | **Автопубликация отклонена** |

## Какие гипотезы закрыл B2

- `A1` — убита двухэтапная схема;
- `A4` — убит постоянный critic;
- `A5` — GLM выбрана среди трёх моделей;
- RAT получил технический диагноз, но не выдавался за пользовательский эксперимент;
- `A3` на малом банке не решалась окончательно и была правильно перенесена в B3-SCALE;
- `A2` была правильно перенесена в B3, где research можно проверить внутри реального E2E.

## Сдвиг после B2

До B2 архитектура могла стать дорогим каскадом из двух промптов, critic и model fallback. После B2 остался простой один проход GLM, детерминированные проверки evidence/schema и обязательная прозрачная очередь. Сложность сохранили только там, где она позже доказала ценность.

## Чего B2 не утверждает

- пользовательскую ценность всего продукта;
- реальную экономию 3–4 часов;
- достаточность короткой повестки;
- финальную стратегию embeddings на растущем банке;
- автономную публикацию.

## Готовый тезис для слайда

> B2 сравнил AI-компоненты до полного E2E. One-pass оказался рациональнее двух проходов, GLM — сильнее двух альтернатив на validation, critic не окупился. Свежий holdout подтвердил техническую стабильность и evidence-grounding, но показал, что релевантность и роли пока требуют review — поэтому автономную публикацию мы сознательно отклонили.
