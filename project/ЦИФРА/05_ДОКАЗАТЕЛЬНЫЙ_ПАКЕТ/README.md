# Доказательный пакет: гипотезы → EXP → B1–B4 → архитектура

> **Одна точка входа для команды, эксперта и будущей презентации.** Здесь не лежат копии тысяч сырых артефактов: каждый вывод ведёт к конкретному эксперименту, runner, входу и сохранённому результату.

## Вся логика одной строкой

`реальные способы сбора → качество отдельных AI-механизмов → совместная работа полного агента → содержательная ценность результата → выбранная архитектура`

## Какие гипотезы закрыты

| Гипотеза — полная формулировка | EXP | Решение |
|---|---|---|
| `H1`: **Гибрид постоянного мониторинга заданных источников и LLM-поиска даст больше значимых материалов, чем каждый режим отдельно, без неприемлемого роста шума и времени проверки.** | B3: fixed / search / hybrid | **Исходная always-on версия убита.** Основа — постоянный сбор; поиск только целевой. |
| `H2`: **Проверка только сомнительных и критичных элементов рабочего потока сохранит необходимое качество и займёт меньше человеческого времени, чем проверка каждого материала перед сборкой выпуска.** | B4: review-all / risk-only | **Подтверждена на Context Truth в части качества и объёма:** 28/28 рисков, очередь 39 вместо 58. Реальные минуты не измерены. |
| `H3`: **Связанные публикации можно объединять в одно событие, сокращая объём просмотра без потери уникальных фактов и разных позиций источников.** | B3+B4: flat / exact / event | **Подтверждена:** связи собраны без потери обязательных фактов. |
| `H4`: **Автоматическая подготовка отдельных представлений одного общего потока для PR и GR уменьшит количество нерелевантных материалов, которые каждому специалисту приходится вручную исключать, по сравнению с одной общей выдачей, при этом материалы, важные для обоих направлений, и общее критичное ядро останутся видимыми каждому.** | B4: общий поток / строгая адресация | **Строгая версия убита:** ролевые ошибки делают скрытие небезопасным. |
| `H5`: **Короткой итоговой повестки с раскрываемыми исходниками будет достаточно получателю, чтобы увидеть главное и всё критичное без обязательного чтения рабочего потока PR/GR.** | B4: рабочий поток / итоговые объекты | **Подтверждена по содержанию:** 18/18 объектов сохранили обязательное. Поведение человека не измерено. |
| `A1`: **Разделение на `извлечь сигналы и факты → оценить их по контексту GS Labs` даст меньше пропусков и ошибок адресации, чем один промпт, сразу формирующий готовые карточки, без неприемлемого роста времени и стоимости.** | B2: one-pass / two-pass | **Убита:** второй проход не дал соразмерного прироста. |
| `A2`: **Целевой доресерч важных и неполных сигналов через reasoning-агента с Tavily повысит полноту и доказательность анализа относительно работы только с первичным материалом без неприемлемого роста шума, задержки и стоимости.** | B3: without / targeted research | **Полная версия убита:** полезность есть, но задержка и смысловые расширения неприемлемы для постоянного контура. Принят целевой асинхронный режим. |
| `A3`: **Предварительный выбор двадцати ближайших событий по embeddings сохранит настоящую связь не хуже полного LLM-обхода доступного банка, резко сократив объём контекста, число сравнений, задержку и стоимость.** | B3-SCALE: full scan / top-20 | **Подтверждена как candidate retrieval:** top-20 сохранил все размеченные связи; full scan упёрся в контекст. |
| `A4`: **Дополнительная LLM-проверка карточки по исходному материалу снизит число неподтверждённых фактов, критичных пропусков и ошибок важности достаточно сильно, чтобы оправдать второй вызов, задержку и стоимость.** | B2: without / with critic | **Убита:** качества не добавил, задержку и вызовы добавил. |

## Полная трассировка: проблема → EXP → сдвиг

| Исходная проблема | Проверяемая ставка | Где проверено | Наблюдение | Что изменили |
|---|---|---|---|---|
| `P1` — специалист вручную обходит разрозненные источники | `H1` и техническая жизнеспособность ingestion | `EXP-B1-C1…C4`, `EXP-B3-02` | Сбор устойчив; search-only неполон; постоянный hybrid добавляет шум | Постоянные источники стали базой, поиск — целевым расширением |
| `P2` — каждый материал вручную читается, фильтруется и пересказывается | `A1`, `A2`, `A4`, `H2` | `EXP-B2-01`, `EXP-B2-03`, `EXP-B3-03`, `EXP-B4-02` | Two-pass и critic не окупились; research полезен только точечно; известные риски можно выделить | One-pass GLM, явные evidence/unknowns, targeted async research, risk-based review |
| `P3` — повторы и ручная упаковка создают тяжёлый результат | `H3`, `H4`, `H5`, `A3` | `EXP-B3-04…05`, `EXP-B4-03…05` | События и короткий слой сохраняют содержание; строгие роли дают пропуски; full scan не масштабируется | Событийная модель, embeddings top-20 с первого дня, общая очередь с фильтрами, lossless top layer |
| Сквозной НПА-сценарий | корректная identity/relation/stage, история и завершение мониторинга | `EXP-B2-04`, `EXP-B3-01`, `EXP-B3-03…04`, `EXP-B3-06` | Новый и известный НПА проходят E2E; до даты действия архив запрещён, после неё явная архивация сохраняет 3/3 версии | НПА хранится как долгоживущий объект; официальный источник главнее Tavily; архив не равен удалению |
| Главная ценностная гипотеза | весь review-first путь против ручного процесса | `EXP-B3-01`, `EXP-B4-02…05` | Короткий трассируемый результат и меньшая review-очередь подтверждены; часы человека не измерены | Автоматический контур заморожен; следующим внешним шагом остаётся cross-over `Excel ↔ MVP` |

Названия EXP кликабельны внутри [B1](./B1_ТЕХНИЧЕСКИЙ_СБОР/ЭКСПЕРИМЕНТЫ/README.md), [B2](./B2_AI_АНАЛИЗ/ЭКСПЕРИМЕНТЫ/README.md), [B3](./B3_АВТОМАТИЧЕСКИЙ_E2E/ЭКСПЕРИМЕНТЫ/README.md) и [B4](./B4_КОНТЕКСТНАЯ_ОЦЕНКА/ЭКСПЕРИМЕНТЫ/README.md).

## Главная ценностная гипотеза

> **На одной и той же суточной повестке AI-система существенно сократит активное ручное время PR/GR на получение, проверку и упаковку материалов, а получателю даст компактную повестку, которую можно разобрать в пределах пользовательского ориентира кейсодателя, без потери критичного и без фактов, которых нет в первоисточниках.**

На внутренней границе она **подтверждена содержательно**: агент создаёт трассируемый короткий результат, сохраняет критичное и уменьшает объём обязательной проверки. Фактические часы живых PR/GR не измерялись и не подменяются синтетическим числом. Это ограничение внешней валидности, а не незакрытая техническая развилка.

## Правило доказательности

- число приводится только вместе с размером набора;
- замороженный вход отделён от выхода агента и gold;
- средний score не скрывает critical miss, ложный статус НПА или неподтверждённый факт;
- отрицательный EXP не считается поражением: он обязан изменить архитектуру;
- Context Truth — честная реконструкция команды по кейсу, чату, созвону и Excel, но не разметка заказчика;
- пользовательское время и удобство не приписываются B1–B4.

## Готовый тезис для слайда

> Мы не подбирали архитектуру по вкусу. B1 доказал технический сбор, B2 выбрал AI-конфигурацию, B3 проверил её в полном потоке и на масштабе, B4 проверил содержательный результат по контексту GS Labs. Отрицательные EXP убрали search-only, always-on hybrid, два обязательных AI-прохода, постоянный critic, обязательный доресерч и жёсткое разделение PR/GR; подтверждённые EXP оставили событийную группировку, выборочную проверку, короткую повестку и embeddings на растущем банке.
