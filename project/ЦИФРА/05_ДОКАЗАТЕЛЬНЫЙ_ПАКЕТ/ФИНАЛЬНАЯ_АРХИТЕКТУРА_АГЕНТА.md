# Финальная выбранная архитектура основного агента

> **Статус:** заморожена по результатам B1–B4. Это архитектура автоматического контура до черновика выпуска; ручная работа PR/GR и дальнейшее управленческое решение находятся после него.

## Контур одной строкой

`источники → RawDocument → PreparedDocument → one-pass GLM → evidence + unknowns → целевой research → embeddings top-20 → GLM-связь → событие/НПА → risk-based review → общая очередь → короткая повестка`

## Основной алгоритм

```text
RSS / Telegram / HTML / sitemap / Tavily / ручной материал
                           │
                           ▼
              [1] Адаптеры + Collector
              checkpoint · дата · URL · original
                           │
                           ▼
             [2] RawDocument → PreparedDocument
              очистка без продуктовых выводов
                           │
                           ▼
                 [3] One-pass GLM
       0..N сигналов · relevance · importance · PR/GR
       facts · verbatim evidence · unknowns · questions
                           │
             ┌─────────────┴─────────────┐
             ▼                           ▼
 [4A] обычный быстрый путь     [4B] high/critical + пробел
                                         │
                                         ▼
                              async Tavily research
                              результат всегда review
             └─────────────┬─────────────┘
                           ▼
             [5] Поиск предметного объекта
       embedding каждого сигнала → top-20 кандидатов → GLM
       точный официальный ID НПА всегда имеет приоритет
                           │
              ┌────────────┴────────────┐
              ▼                         ▼
       NewsEvent                 NpaRecord + versions
              └────────────┬────────────┘
                           ▼
                 [6] Safety + review
       schema · evidence · risk flag · degraded state
                           │
                           ▼
          [7] Общая очередь с фильтрами PR/GR
       критичное видно PR, GR и HEAD; роли ничего не скрывают
                           │
                           ▼
            [8] Lossless короткая повестка
       claims · sources · unknowns · research questions
```

## Почему именно так

| Решение | Чем обусловлено |
|---|---|
| Постоянные источники — основа | `H1`: search-only нашёл меньше объектов; always-on hybrid добавил шум |
| Один GLM-проход | `A1`: two-pass был медленнее и не улучшил целевое качество |
| Без постоянного AI-critic | `A4`: второй вызов не улучшил итоговые показатели |
| Research только целевой и асинхронный | `A2`: появились полезные факты, но также смысловые расширения и 76–201 с задержки |
| Embeddings top-20 используются всегда | Банк начинает расти с первого рабочего дня; `A3` показала, что top-20 сохраняет размеченные связи и не упирается в размер контекста. Full scan остаётся только benchmark-контролем и аварийным fallback |
| Событие вместо набора публикаций | `H3`: сокращает объекты без потери источников и разных позиций |
| Review-first | B2 выявил недостаточную автономную релевантность, роли и event linking |
| Одна общая очередь, роли — фильтры | `H4`: строгая адресация дала пропуски и лишние роли |
| Unknowns видимы в коротком результате | B4 нашёл потерю неопределённости при старой проекции |
| Критичное — общее ядро | D1 после исправления прошёл 3/3 ролевых решений |

## Технологии выбранного контура

| Граница | Реализация |
|---|---|
| Сбор | Python, `httpx`, `feedparser`, `trafilatura`, `selectolax`, Telethon/web-preview |
| Генеративный AI | `glm-5.3-flash:cloud` через Ollama-compatible provider |
| Embeddings | `google/gemini-embedding-001` через OpenRouter |
| Поиск | Tavily; не считается юридическим первоисточником |
| Хранилище MVP | SQLite с трассировкой original → analysis → object → release |
| API | тонкий Python HTTP API над product services |
| Интерфейс MVP | статический HTML/CSS/JavaScript |

## Отказные режимы

- источник недоступен — остальные продолжают работу, ошибка видна;
- LLM недоступна — original сохраняется, объект получает `degraded/needs_review`;
- embeddings недоступны — точные ID НПА связываются, неоднозначное не склеивается автоматически;
- relation неоднозначна — отдельные объекты до review;
- research не сработал — основной сигнал не теряется;
- повторный запуск — не создаёт второй документ;
- ручная правка — не затирается новым AI-запуском.

## Политика банка

- embedding рассчитывается при создании каждого новостного события и НПА;
- обычное новостное событие остаётся активным **30 календарных дней после последнего содержательного обновления**; простая перепубликация без нового факта срок не продлевает;
- в первый день каждого месяца maintenance-job переносит подходящие события в логический архив; событие не архивируется, пока оно требует проверки либо входит в активный черновик выпуска;
- архив не исключается из смыслового поиска: embeddings top-20 выбирает кандидатов среди активных и архивных событий;
- новый факт или развитие архивного события создаёт новую версию и возвращает его в активный банк; повтор без нового факта только добавляет источник, а связанная новая тема создаётся отдельным событием;
- в MVP архив хранится без физического удаления: сохраняются оригиналы, evidence, связи, версии, embeddings, выпуски и audit trail;
- НПА не очищаются по месячному правилу: они остаются активными до завершения жизненного цикла и затем архивируются вместе со всеми версиями;
- принятый НПА с будущей датой действия остаётся активным до этой даты; архивирование выполняется явно и идемпотентно;
- в рабочем контуре кандидаты всегда выбираются через embeddings top-20, после чего связь решает GLM;
- full scan не является штатным режимом продукта: он нужен для контрольных EXP и как диагностический fallback.

Архивация и хранение — разные вещи: архив убирает старое событие из рабочей очереди, но не уничтожает доказательства и не делает прошлое невидимым для дедупликации. Физический срок удаления данных для промышленной эксплуатации должен быть согласован с GS Labs; в MVP автоматического физического удаления нет.

## Граница продукта

Агент не принимает решение за компанию. Он собирает, объясняет, связывает, приоритизирует и готовит проверяемый черновик. PR/GR подтверждает или исправляет его; руководитель или подразделение получает готовую повестку и действует уже вне продукта.
