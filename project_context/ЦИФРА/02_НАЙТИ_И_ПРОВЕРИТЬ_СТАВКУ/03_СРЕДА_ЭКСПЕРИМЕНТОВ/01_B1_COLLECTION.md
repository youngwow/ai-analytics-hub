# B1 Collection — канонический документ

> **Версия:** 2.0  
> **Заморожено до оцениваемого запуска:** 05.09.2026  
> **Правило:** критерии ниже после результата не меняются. Исправление продукта создаёт новый run, а не новую удобную метрику.

## Один вопрос

Может ли выбранный ingestion-контур технически надёжно превращать доступные поверхности настроенных источников в сохраняемые `RawDocument`, не терять известные fixture-публикации, не плодить повторы, явно показывать частичные сбои и выдерживать выбранный уровень параллелизма?

`B1` не решает, полезна ли новость GS Labs, не оценивает шум Tavily, саммари, важность, события и интерфейс. Это `B2/B3`.

## Решение об объёме — без перегруза

Проверяются только способы, которые уже используются или готовы к включению:

- RSS/Atom и дотягивание fulltext;
- Telegram public web-preview;
- HTML list/diff;
- sitemap;
- Tavily search как выключенный по умолчанию дополнительный вход;
- общие состояние, persistence, изоляция ошибок и повторный запуск.

Не строим сейчас generic JSON API, headless browser, OCR, email, paywall bypass и нагрузочный генератор для чужих сайтов. Они не нужны для текущих 44 активных входов. Если такая поверхность войдёт в MVP, для неё появится отдельный контракт до реализации.

MTProto не является gate текущей конфигурации: пользователь разрешил web-preview как MVP-транспорт. MTProto проверяется позже только при решении сделать его основным.

## Четыре независимых слоя

### C1. Exact contract

На замороженных fixtures проверяются RSS, Atom, Telegram, HTML, sitemap, search и fulltext.

Ground truth — явный manifest, созданный до запуска. Scorer сравнивает:

- точный набор `external_id`;
- отсутствие неизвестных документов;
- обязательные поля;
- attachments там, где они присутствуют;
- ожидаемые cursor/validator.

**Gate:** `recall=100%`, `false positives=0`, обязательные поля `100%` по каждому сценарию. Среднее не скрывает провал.

### C2. State and fault

Минимальная матрица:

- `200 → 304`;
- первый запуск → повтор без дублей;
- Telegram `before → after` с курсором;
- timeout → восстановление;
- `403`, `429`, `500`, повреждённый формат;
- один упавший источник не останавливает соседний;
- ошибка дочернего sitemap не маскируется чистым `ok`.

**Gate:** все критичные сценарии проходят; после recovery нет потери доступного fixture-документа; повтор создаёт `0` новых записей.

### C3. Full Collector replay

Один сохранённый live snapshot активных входов прогоняется через полный путь:

`adapter → window/dedup → fulltext → normalization → SQLite persistence`.

Чистые БД и одинаковые байты используются при `concurrency=1/8/24`.

Измеряются:

- полный wall time;
- fingerprint сохранённых документов;
- source status и warnings;
- replay misses;
- полные и fallback-документы;
- CPU и peak RSS;
- второй проход без новых записей на отдельном stateful core.

**Gate:** fingerprint и число документов одинаковы при `1/8/24`, replay misses `0`, скрытых partial failures `0`. Побеждает самая быстрая конфигурация, прошедшая корректность; разница меньше 10% считается ничьёй и выбирается меньшая concurrency.

### C4. Live compatibility

Три умеренных живых прохода:

1. **active:** только включённые источники — это verdict MVP;
2. **registered:** выключенные входы проверяются отдельно как кандидаты и не ухудшают статус активной конфигурации;
3. каждый HTTP body и Tavily request/response сохраняется с hash без credentials.

Внешние сайты намеренно не подвергаются искусственной нагрузке.

**Gate active:** нет необъяснённого полного отказа активного метода; subrequest errors видны отдельно; у каждого сохранённого документа есть источник, `external_id`, URL либо явно типизированный digest, заголовок и читаемое содержимое. Live не используется для заявления абсолютного recall.

## Правильные метрики

### Корректность

- exact recall и false positives на C1;
- required-field accuracy;
- duplicate writes;
- recovery loss;
- concurrency fingerprint equality.

### Надёжность

- `ok / partial / failed` отдельно;
- HTTP/subrequest failures отдельно от верхнего статуса адаптера;
- доля источников без ошибки за три live-run;
- replay misses и недетерминированные fingerprints.

### Полнота технического документа

Отдельно, без смешивания:

- surface content из RSS/Telegram/search;
- attempted/succeeded fulltext;
- fallback content после неудачного fulltext;
- title, published_at, source identity, original URL, attachments.

`text OR summary` больше не называется успешным fulltext.

### Скорость

- live latency поверхностей;
- полный wall time Collector;
- replay wall time и throughput внутри нашего контура;
- CPU и память.

RSS, Telegram, HTML, sitemap и search не получают единого «лучшего» балла: это разные входы. Показываются отдельные таблицы покрытия, корректности, live-скорости и ограничений. Итоговый приоритет — архитектурное решение, а не арифметическая смесь несопоставимых величин.

## SLA кейса

B1 измеряет время обработки после начала опроса. Полный `published → available` требует работающего scheduler и длительного наблюдения, которых сейчас нет.

Поэтому допускается только условный вывод:

`максимальный polling interval + measured processing p95 ≤ 15 минут`,  
для регуляторов: `≤ 60 минут`.

Без scheduler нельзя заявлять, что SLA уже доказан.

## Возможные решения

- **PASS:** C1–C3 прошли, active C4 не имеет скрытых критичных провалов; выбран concurrency и названы ограничения.
- **MIXED:** основа пригодна, но конкретный активный источник/метод требует fallback, отключения или локального исправления.
- **FAIL:** теряются fixture-документы, результат зависит от concurrency, ошибка источника ломает общий прогон или активный вход нельзя технически получить.

Контракт и пороги продублированы в `benchmarks/b1_proof/contract.json`. SHA-256 фиксируется рядом до первого запуска новой версии.

## Результат B1 v2

**Verdict: `PASS` с одним явно видимым ограничением активного источника.** Контракт `v2.0.0` был заморожен до оцениваемого запуска; SHA-256: `9401ee96b343369a6d48f307c3f9ac8d34eb09c79de6a7f80f578b91ed4d9715`.

### C1 — exact contract: PASS

- `8/8` сценариев RSS, Atom, Telegram, HTML, sitemap и Tavily совпали с замороженным exact-output;
- recall `100%`, неизвестных `external_id` — `0`, обязательные поля — `100%`;
- отдельный exact-check fulltext извлёк ожидаемые заголовок, автора, дату и текст.

### C2 — state and fault: PASS

Пройдены `200→304`, повтор без дублей, Telegram cursor, timeout→recovery, `403/429/500`, повреждённый feed, изоляция источника и видимый child-sitemap failure. Найденный ранее скрытый `500` исправлен: recoverable subrequest теперь даёт `partial` и warning.

### C3 — full Collector replay: PASS

На одинаковом сохранённом live-snapshot полный контур сохранил `106` документов с одним fingerprint при `concurrency=1/8/24`; replay misses — `0`.

| Concurrency | Wall time | Результат |
|---:|---:|---|
| 1 | 2908 ms | корректен |
| 8 | 1590 ms | корректен, выбран |
| 24 | 1555 ms | корректен, но быстрее лишь на 2.2% и требует больше памяти |

**Решение:** оставить `concurrency=8`: он входит в 10%-ную ничью с 24 и является меньшей конфигурацией.

### C4 — live compatibility: PASS

- три прохода по `44` активным источникам: `132` source-attempts;
- `129 ok`, `3 partial`, `0 failed`; partial во всех трёх случаях — один дочерний sitemap РФРИТ;
- сохранено `318` документов; у всех есть источник, `external_id`, URL, заголовок и читаемое содержимое;
- fulltext: `183/192` извлечено с оригинальных страниц, ещё `9/192` имеют fallback-текст из ленты;
- длительность полного прохода: `37.1–40.9 с`;
- найдено `0` попаданий credentials в сохранённые артефакты.

Отдельная диагностика `9` выключенных входов дала `9 ok`, `21` документ и `0` утечек. Она не влияет на verdict MVP. В частности, ТАСС сохраняет содержимое из RSS как fallback, но его fulltext страницы не извлекается — поэтому источник остаётся выключенным.

## Что исправлено по результату

1. Дочерний сбой sitemap больше не маскируется чистым `ok`.
2. В отчёте разделены `ok / partial / failed`.
3. Fulltext разделён на `attempted / extracted / fallback`; `text OR summary` больше не выдаётся за fulltext-success.
4. Persistence сделан детерминированным: результат глобальной URL-дедупликации не зависит от порядка завершения потоков.
5. Exact-наборы закреплены hash-значениями; scorer проверяет их целиком.
6. Артефакты автоматически проверяются на обязательные поля и утечки секретов.

## Граница доказанного

B1 подтверждает техническую работоспособность текущего ingestion на настроенных поверхностях. Он **не** доказывает абсолютную полноту живого интернета, смысловую релевантность GS Labs, качество AI, Telegram MTProto и SLA `publication→feed`: для последнего ещё нужен scheduler и длительное наблюдение. Стабильный `partial` РФРИТ не скрыт и должен быть устранён fallback-источником либо конфигурацией sitemap перед пилотом.
